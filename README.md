# Тестовое задание

## Запуск

```bash
cd php-test
docker compose up -d

# ключи капчи
export CAPTCHA_SITEKEY='ключ клиента'
export CAPTCHA_SECRET='ключ сервера'

# приложение
php -S 127.0.0.1:8000 -t public
```

Открыть `http://127.0.0.1:8000/`.

Проверка, что всё сошлось:

```bash
curl -i http://127.0.0.1:8000/
docker compose ps                         
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DB_DSN` | `mysql:host=127.0.0.1;port=3306;dbname=php_test;charset=utf8mb4` | строка подключения PDO |
| `DB_USER` | `app` | пользователь БД |
| `DB_PASS` | `apppass` | пароль БД |
| `CAPTCHA_SITEKEY` | пусто | публичный ключ SmartCaptcha, попадает в HTML |
| `CAPTCHA_SECRET` | пусто | серверный ключ SmartCaptcha, **только** в запросе к `/validate` |

Значения по умолчанию совпадают с `docker-compose.yaml`, поэтому локально достаточно только ключей капчи. Секреты не хранятся в коде и не коммитятся: `config.php` читает их через `getenv()`.

## Структура

```
docker-compose.yaml     MySQL 8.4, порт 127.0.0.1:3306, данные в ./data/mysql
schema.mysql.sql        таблица users, применяется при первой инициализации БД
src/config.php          конфиг: DSN и ключи капчи из окружения
src/db.php              get_pdo(array $config): PDO
src/captcha.php         verify_captcha(): серверная проверка токена SmartCaptcha
src/bootstrap.php       подключается каждой страницей: конфиг, PDO, старт сессии
public/index.php        главная: flash-сообщение, ссылки, приветствие залогиненного
public/register.php     форма + обработка регистрации
public/login.php        форма + обработка входа (с капчей)
public/profile.php      закрытая страница: чтение и изменение своих данных
```

`public` — единственный каталог, отдаваемый веб-сервером. Всё, что в `src`, снаружи недоступно: конфиг и функции нельзя скачать как текст.

## Как это работает

**Регистрация.** Валидация (имя не пустое, email по `filter_var`, телефон — 11 цифр после нормализации, пароли совпадают) → проверка дубликатов двумя `SELECT` → `password_hash()` → `INSERT` в `try/catch` → flash-сообщение и редирект на главную.

**Вход.** Капча проверяется на сервере → логин нормализуется (email к нижнему регистру, телефон к 11 цифрам) → один запрос `WHERE email = :login OR phone = :login` → `password_verify()` → `session_regenerate_id(true)` → `user_id` в сессию → редирект в профиль.

**Профиль.** Без `user_id` в сессии — редирект на главную. Данные читаются из БД, форма предзаполнена. Сохранение: валидация → проверка дубликатов **с исключением себя** → `UPDATE` (пароль обновляется только если поле заполнено) → flash и редирект (PRG, чтобы F5 не отправлял форму повторно).

## Капча

Используется Yandex SmartCaptcha. Клиентский ключ уходит в HTML (`data-sitekey`), серверный — только в POST на `https://smartcaptcha.cloud.yandex.ru/validate`. Токен из формы — обычная строка, поэтому единственный достоверный факт — ответ сервиса капчи.
